## 下一步：完成剧库真实闭环

需要在后端仓库中实现并联调以下能力，然后以实际响应完成 `DramaRepository` 的 HTTP 适配器。

| 能力      | 前端所需信息                                                                   | 后端必须保证                                 |
| --------- | ------------------------------------------------------------------------------ | -------------------------------------------- |
| 剧集查询  | ID、标题、简介、标签、角标、状态、免费集数、集数统计、封面、定时时间、更新时间 | 过滤、分页、权限校验；空数据与错误有明确区别 |
| 新建/编辑 | 剧集基本字段，成功后返回保存结果                                               | 字段校验、内容写权限、操作日志               |
| 封面上传  | 实际存储地址、上传状态、错误                                                   | 文件格式/体积校验、存储、访问控制            |
| 分集管理  | 集号、媒体文件、时长、转码状态、上架状态                                       | 集号一致性、真实上传/转码、失败重试          |
| 上下架    | 服务端更新结果、不能上架的具体原因                                             | 必需分集已转码、合法免费集范围、权限和审计   |
| 定时上架  | 明确的时区与时间格式、任务执行状态                                             | 服务端调度、幂等执行、失败记录               |

端点路径、数据库字段命名、日期/时区和响应格式需按后端实际实现确认；前端不预设它们已存在。上传和转码不在本地用延时模拟。

后续顺序：剧库闭环 → 角色审核 → AI 生成任务与候选入库 → 标签/分类/运营位 → 用户与客服 → 激励/推送 → 商业化及二人审批 → 配置/协议发布。
