## 与原型相比补齐的行为

- 列表实现真实前端分页；搜索与筛选重置页码；空结果展示空态。
- 按账号隔离本地数据；页面切换和刷新保留数据；不保存密码或令牌到业务数据中。
- 多语言分类完整保存 7 语言内容及生效时段，重新打开编辑仍可恢复。
- 数字字段、必填内容、观看间隔、协议格式 / 10MB 限制、生效时间顺序校验。
- 正式入口沿用服务端权限；只读账号的写入按钮禁用并在事件层阻止写操作。
- 工作区切换 / 卸载清理异步定时器，避免生成 / 转码结束后操作已销毁的页面。
- 登录后的 redirect 支持新增业务路由；保留原来的刷新恢复登录逻辑。

## 本地预览与后端边界

无需登录的预览入口：`/#/preview/cands`。其他页面：`/#/preview/<页面标识>`，例如 `/#/preview/plans`。预览用独立的本地数据空间，系统账号 / 权限 / 日志在预览中也为示例；不会请求账号管理接口。登录页提供预览链接。

正式页面中，账号、角色、日志继续走已有 `/admin/v1` 接口；其余未接入业务显示待接入状态。以下行为仅限开发原型：AI 使用本地规则生成草案，视频转码为延时状态模拟，协议仅保存文件元数据。原型发布及二人审批不会修改线上配置、用户余额、真正上传文件、发送推送或邮件。

后端正式接入需提供各模块的查询 / 写入、服务端分页、发布版本与审批、实际文件存储 / 转码、AI 生成任务及推送执行接口。`/auth/me` 的 `permissions` 需包含相应分组：`overview`、`content`、`ops`、`users`、`commerce`、`ai`、`tasks`、`push`、`service`、`system`，取值 `r` / `rw`。前端不会为缺失权限自行授权。
